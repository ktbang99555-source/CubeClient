# CubeClient — 런처 UI 및 로그인 연결 설계

## 배경

런처 코어(Sub-project A)는 동작한다. 1.21.4 바닐라와 Fabric 모두 실제로 게임 창이 뜨고,
Microsoft 로그인도 전체 체인이 통과한다(닉네임 `Mal_itIIyr` 확인).

문제는 UI다. 현재 `ui/renderer/`에는 **CSS가 한 줄도 없다.** 스타일 없는 `<div>`와 `<button>`만
있어서 런처라기보다 테스트 페이지에 가깝다. 그리고 `login` 백엔드 명령은 완성됐지만 화면에서
누를 수 있는 경로가 없다.

이 문서는 두 가지를 함께 다룬다. 로그인 UI는 결국 런처 셸 안에 들어가므로 따로 설계하면
두 번 일하게 된다.

## 시각 방향: Deepslate

세 방향(Deepslate / Copper Workbench / Hotbar)을 만들어 비교한 뒤 **Deepslate**를 선택했다.
레퍼런스로 제시된 Lunar Client와 같은 계열이면서, 지금처럼 버전이 1~2개일 때 구조가 잘 맞는다.

**색**
| 역할 | 값 | 비고 |
|---|---|---|
| 바닥 | `#0f1216` | 깊은 청회색. 순수 검정이 아니라 약간 푸른 기가 있다 |
| 패널 | `#151a20` | 히어로·칩 배경 |
| 테두리 | `#232932` | |
| 본문 | `#e4e8ee` | |
| 흐린 글자 | `#8a94a3` | 라벨, 부제 |
| 강조 | `#2fa968` | 에메랄드. Lunar의 형광 초록보다 채도를 낮춰 눈이 덜 피로하다 |
| 경고 | `#e0a23c` | 로그인 안 됨, 비정상 종료 |

**타이포**: 시스템 스택만 쓴다. Electron이라 CDN 폰트를 받을 수 있지만, 오프라인에서 조용히
폴백되는 것보다 처음부터 시스템 폰트로 확정하는 편이 낫다. 숫자가 들어가는 곳(버전, FPS,
진행 개수)은 `font-variant-numeric: tabular-nums`가 붙은 등폭 스택을 쓴다.

**모양**: 라운드 10~14px, 강조색은 실행 버튼 한 곳에만 쓴다.

**단일 테마**: 다크 전용이다. 게임 런처가 다크에 고정되는 것은 의도된 선택이며, 라이트 테마는
만들지 않는다.

### 용어

**"프로필"이라는 말을 UI에서 쓰지 않는다.** 계정으로 읽히기 때문이다. 화면에서는 **"버전"**이라고
부른다. 내부 데이터 구조(`Profile` 레코드)는 그대로 둔다 — 실제로 버전 설정을 담고 있어
코드에서는 정확한 이름이다.

**계정과 버전은 화면상 완전히 분리한다.** 계정은 타이틀바 우측 한 곳에만, 버전은 히어로
드롭다운에만 나타난다. 두 개념이 같은 영역에 섞이지 않는다.

### 아이콘 레일

홈 / 버전 / 로그 / 설정 네 개. 전부 실제로 데이터가 있는 것만이다. 친구·뉴스·스토어처럼
백엔드가 없는 항목은 넣지 않는다 — 빈 껍데기는 완성도를 떨어뜨린다.

### 히어로: 상태에 따라 바뀌는 한 자리

| 상태 | 표시 |
|---|---|
| 대기 | `PLAY` 버튼 + 그 아래 버전 드롭다운 |
| 준비 중 | 진행 바 + 현재 단계와 개수 (`에셋 1204 / 4040`) |
| 실행 중 | `실행 중…` + 종료 버튼 |

진행 단계는 백엔드가 이미 보내는 것을 그대로 쓴다: `manifest`, `libraries`, `client_jar`,
`assets`, `loader`, `runtime`, `launching`.

### 버전 전환 드롭다운

`1.21.4 · Fabric ▾`를 누르면 설정된 버전 목록이 펼쳐진다. 목록은 `list-profiles`가 반환하는
것을 그대로 쓴다. 맨 아래 `+ 버전 추가`는 이번 범위에 포함하지 않고 비활성으로 둔다
(버전 추가 화면은 별도 작업).

### 프레임 없는 창

`frame: false`로 만들고 타이틀바를 직접 그린다. 드래그 영역은 `-webkit-app-region: drag`,
버튼들은 `no-drag`. 최소화·최대화·닫기는 preload를 통해 main으로 보낸다.

## 로그인 흐름

백엔드 `login` 명령은 완성돼 있다. 화면에서 부를 경로만 만든다.

1. **로그인 전** — 타이틀바에 `로그인` 버튼. 히어로의 PLAY는 여전히 누를 수 있지만 상태 줄에
   `오프라인 세션 — 서버 접속 불가` 경고가 뜬다.
2. **로그인 클릭** — 모달이 열리고 백엔드 `login`이 시작된다.
3. **코드 표시** — `device_code` 이벤트가 오면 모달에 **큰 글씨로 코드**와 두 버튼:
   `코드 복사`, `브라우저에서 열기`. 사용자가 브라우저에서 완료할 때까지 모달은 대기 문구를
   유지한다. 백엔드가 5초 간격으로 폴링한다.
4. **성공** — `login_success`(토큰이 제거된 것)가 오면 모달이 닫히고 타이틀바가 닉네임으로
   바뀐다.
5. **실패** — 모달에 사유를 그대로 보여준다. 백엔드가 이미 사람이 읽을 수 있는 메시지를
   만든다: Xbox 프로필 없음, 미성년 계정, 지역 제한, 코드 만료 등.
6. **취소** — 모달을 닫으면 백엔드 프로세스를 종료한다.

### 토큰은 렌더러로 가지 않는다

기존 설계를 그대로 유지한다. 백엔드는 토큰을 전용 `auth_result` 이벤트로만 보내고,
`sanitizeForRenderer`의 타입 허용목록이 이를 막는다. 모달은 닉네임만 받는다. 이 설계는
이미 테스트로 고정돼 있으므로 이번 작업에서 건드리지 않는다.

## 파일 구성

```
ui/
├─ main.js                  창을 frame:false 로, 창 제어 IPC 추가
├─ preload.js               minimize/maximize/close, startLogin, cancelLogin 노출
└─ renderer/
   ├─ index.html            셸 뼈대 (타이틀바 · 레일 · 메인 · 모달 컨테이너)
   ├─ styles.css            토큰 + 컴포넌트 (신규)
   ├─ renderer.js           이벤트 배선만 (얇게 유지)
   └─ components/
      ├─ hero.js            대기/준비중/실행중 세 상태 렌더
      ├─ versionMenu.js     버전 드롭다운
      ├─ statusBar.js       런타임·마지막 실행·로그
      └─ loginModal.js      코드 표시, 대기, 성공/실패
```

현재 `renderer.js` 하나에 전부 들어 있는 것을 컴포넌트로 나눈다. 각 파일은 순수 DOM 함수만
내보내고 Electron을 직접 참조하지 않는다 — 지금처럼 jsdom에서 테스트할 수 있어야 한다.

## 오류 처리

- **백엔드가 뜨지 않음** (`java` 없음 등) — `backendProcess`가 이미 `error` 이벤트로 바꿔준다.
  히어로 자리에 에러와 재시도 버튼을 띄운다.
- **다운로드 실패** — 백엔드 `error` 이벤트를 히어로에 그대로 표시하고 PLAY를 다시 누를 수
  있게 한다. 이미 받은 파일은 체크섬이 맞으면 건너뛰므로 재시도가 싸다.
- **게임 비정상 종료** — 상태 줄의 마지막 실행이 경고색으로 바뀌고 `로그` 버튼을 강조한다.
- **로그인 실패** — 모달에 백엔드 메시지를 그대로. 새 문구를 UI에서 만들지 않는다.

## 테스트

- **컴포넌트** — 각 렌더 함수를 jsdom에서 테스트한다. 히어로의 세 상태 전환, 버전 메뉴가
  목록을 그리는지, 모달이 코드를 표시하는지.
- **토큰 격리** — `sanitizeForRenderer` 테스트가 이미 있다. 여기에 로그인 모달이 `auth_result`를
  받아도 토큰을 그리지 않는다는 테스트를 더한다.
- **시각 확인** — 실제로 Electron을 띄워 눈으로 본다. 창 제어 버튼, 드래그, 드롭다운 동작은
  자동화 테스트로 잡히지 않는다.

## 이번 범위 밖

- **버전 추가/편집 화면** — 드롭다운의 `+ 버전 추가`는 비활성으로 둔다.
- **설정 화면** — 레일에 아이콘만 두고 내용은 비운다.
- **계정 여러 개** — 하나만 저장한다. 전환 UI 없음.
- **토큰 갱신** — 저장된 토큰은 약 하루 뒤 만료된다. 만료 시 재로그인해야 한다.
