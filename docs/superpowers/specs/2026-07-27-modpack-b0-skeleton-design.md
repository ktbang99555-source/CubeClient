# CubeClient 모드팩 — B0: 모드 골격 + 모드 목록 화면

## 배경

Sub-project A(런처)는 완료됐다. Microsoft 로그인 → 버전 설치 → 실행 → 온라인 서버 접속까지
실기기에서 검증됐다.

Sub-project B는 1.21.x용 자체 Fabric 모드팩이다. 요청받은 기능은 13개다:

- **HUD**: FPS, 속도, CPS, 핑, 내구도, 콤보 카운터, 리소스팩 표시, 성능(CPU/RAM)
- **조작**: Toggle Sneak/Sprint, 줌(C)
- **월드**: 미니맵(M), 죽은 위치 표시
- **서버**: 서버 리스트 + 핑

13개 기능과 HUD 위치 편집기, 모드 목록 화면을 한 스펙에 담으면 절반쯤에서 방향이 흔들린다.
그래서 B0~B5로 쪼갠다. 이 문서는 **B0만** 다룬다: 나머지 모든 기능이 등록되는 골격과,
Feather Client류 런처들이 쓰는 "모드 목록 화면" 패턴.

```
B0  모드 골격 + 모드 목록 화면 + FPS(증명용 1개)     ← 이 문서
B1  HUD 프레임워크 + 위치/크기 편집기 + 속도·CPS
B2  나머지 HUD (성능·핑·내구도·콤보·리소스팩)
B3  조작 (Toggle Sneak/Sprint, 줌)
B4  미니맵 + 죽은 위치
B5  서버 리스트 + 핑
```

## 참고 예시와 반영한 점

Feather Client 스크린샷 두 장을 참고했다:

1. 타이틀 화면 우상단에 아이콘 바(계정·아이콘 여러 개), 중앙에 브랜드 패널
2. 일시정지 화면에 **`클라이언트 설정`** 버튼이 바닐라 **`설정`**과 나란히, 별개로 존재
3. 모드 목록 화면: 카드 그리드(아이콘 + 이름 + 켬/끔 버튼 + 톱니 + 하트), 상단 카테고리
   탭(전부/New/HUD/Hypixel/PvP), 검색창

CubeClient는 Feather의 화이트·레드 톤이 아니라 런처에서 이미 확정한 **딥슬레이트** 팔레트를
그대로 쓴다. 브랜드가 하나로 이어지는 게 목적이다.

## 화면 구성

### 진입점

바닐라 **`설정`**과 별개로 **`클라이언트 설정`** 버튼을 추가한다:

- **타이틀 화면** — 기존 버튼 목록 아래
- **일시정지 화면(ESC)** — 기존 `게임으로`/`설정`/`저장하고 나가기` 옆

두 화면 모두 Fabric API의 `ScreenEvents.AFTER_INIT`으로 기존 화면에 버튼을 끼워 넣는다.
화면을 통째로 새로 그리지 않는다 — 바닐라 화면의 나머지 버튼(멀티플레이, 옵션 등)은 그대로
둬야 한다.

### 모드 목록 화면 (`ModListScreen`)

```
┌──────────────────────────────────────────────────────┐
│ ● CubeClient 클라이언트 설정                      ✕  │
├────────────────────────────────────┬─────────────────┤
│ [전부] [HUD] [조작] [월드] [서버]   │ 🔍 모드 검색     │
├──────────────────────────────────────────────────────┤
│  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐     │
│  │  ♡     │  │  ♥     │  │  ♡     │  │  ♡     │     │
│  │  아이콘 │  │  아이콘 │  │  아이콘 │  │  아이콘 │     │
│  │  FPS   │  │  CPS   │  │  줌    │  │  미니맵 │     │
│  │ [켬] ⚙ │  │ [끔] ⚙ │  │ [끔] ⚙ │  │ [끔] ⚙ │     │
│  └────────┘  └────────┘  └────────┘  └────────┘     │
│  (스크롤)                                              │
└──────────────────────────────────────────────────────┘
```

- **카테고리 탭**: 전부 / HUD / 조작 / 월드 / 서버. `Feature`가 스스로 카테고리를 선언한다.
- **검색창**: 이름 부분 일치, 대소문자 무시.
- **카드**: 4열 그리드, 폭에 맞춰 줄바꿈. 아이콘(단순 도형), 이름, 켬/끔 버튼, 톱니(개별
  설정 화면 — B0에는 설정할 게 있는 기능이 없어서 톱니는 항상 비활성), 하트(즐겨찾기).
- **즐겨찾기**: 하트를 누른 기능이 카테고리·검색과 무관하게 항상 목록 맨 앞으로 온다.
- **New/Hypixel/PvP 탭은 이번 범위 밖** — 신규 배지, 서버 자동 감지가 필요해서 나중 문서에서
  다룬다.

### 카드 하나 = 기능 하나

카드를 누르면(톱니가 아니라 켬/끔 버튼 자체를 누르면) 즉시 토글된다. 확인 절차 없음 —
바로 켜지고 바로 꺼진다. 게임 플레이 중에도 열 수 있으므로, 토글 즉시 반영돼야 한다
(다시 열어야 적용되는 방식은 안 됨).

## 아키텍처

### `Feature` — 기능 하나의 계약

```java
public interface Feature {
    String id();              // "fps", "cps" 등. 설정 파일의 키.
    String displayName();     // "FPS 표시"
    Category category();      // HUD, CONTROL, WORLD, SERVER
    void onEnable();
    void onDisable();
}
```

B0에서 만드는 유일한 구현은 `FpsDisplay` — 좌상단에 고정 텍스트로 FPS를 그린다. 위치 편집은
B1의 몫이라 이번엔 좌표가 하드코딩이다.

### `FeatureRegistry`

기능을 `id`로 등록·조회하고, 카테고리/검색/즐겨찾기 순서로 정렬된 목록을 돌려준다. 이후
B1~B5가 각자의 `Feature` 구현을 여기 등록하기만 하면 `ModListScreen`은 코드를 안 건드려도
자동으로 새 카드를 그린다 — 화면과 기능 목록이 분리돼 있다는 뜻이다.

### `ModConfig` — 저장

```json
{
  "enabled": { "fps": true },
  "favorites": ["fps"]
}
```

**저장 위치**: `%APPDATA%/CubeClient/mod-config.json` — 런처의 공용 폴더. 선택한 "계정 전체
공통" 요구사항이 여기서 나온다: 어느 버전(바닐라/Fabric, 1.21.4/이후 버전)으로 켜도 같은
파일을 읽고 쓴다.

모드는 이 경로를 직접 계산하지 않는다. **런처가 JVM 인자로 알려준다**:

```
-Dcubeclient.configDir=C:\Users\...\AppData\Roaming\CubeClient
```

`JvmArgsBuilder`가 이 인자를 추가한다(런처 쪽 변경, B0 계획에 포함). 이 인자가 없으면(모드를
수동으로 다른 런처에 설치한 경우) 모드는 `.minecraft/config/cubeclient/`로 폴백한다 — 그래도
동작은 해야 하고, 크래시로 이어지면 안 된다.

**알 수 없는 id는 버려지지 않고 무시된다.** 예를 들어 B0만 설치된 상태에서 `mod-config.json`에
`"minimap": true`가 남아 있어도(예전에 B4까지 있었다가 되돌린 경우) 파싱은 성공하고, 존재하지
않는 기능은 조용히 건너뛴다. 이러면 나중 버전에서 예전 버전으로 되돌려도 설정 파일이 안
깨진다.

## 모드 배포 — 런처가 자동 설치

사용자가 손으로 mods 폴더에 넣는 걸 요구하지 않는다. `LaunchCommand`가 Fabric 프로필을
실행할 때:

1. `instances/<profileId>/mods/cubeclient-mod.jar`로 우리 모드 jar를 복사(이미 있고 체크섬이
   같으면 건너뜀 — 다운로드 로직과 같은 패턴).
2. **Fabric API도 함께 설치.** 타이틀/일시정지 화면에 버튼을 끼워 넣는 `ScreenEvents`는
   Fabric Loader가 아니라 Fabric API가 제공한다 — 둘은 별개 배포물이다. Fabric API는
   `LoaderInstaller`가 이미 Fabric 로더 라이브러리를 받는 것과 **같은 Maven 저장소**
   (`maven.fabricmc.net`, 좌표 `net.fabricmc.fabric-api:fabric-api`)에 배포되므로, 새 외부
   API를 붙이지 않고 기존 "Maven 좌표 + `.sha1` 시블링으로 검증" 메커니즘을 그대로 재사용한다.
   버전은 대상 마인크래프트 버전(1.21.4)에 맞는 것을 고른다.
3. 바닐라 프로필에는 아무것도 설치하지 않는다 — Fabric 없이는 모드가 로드될 수 없다. 상태
   줄이나 버전 드롭다운에 "이 버전은 모드팩을 지원하지 않습니다" 같은 안내는 이번 범위 밖.

## 오류 처리

- **`mod-config.json`이 손상됨** — 파싱 실패 시 빈 설정으로 시작하고 손상된 파일을
  `mod-config.json.bak`으로 옮긴다(런처의 `latest.log` → `game-<timestamp>.log` 회전과 같은
  패턴 — 조용히 지우지 않는다).
- **설정 저장 중 실패**(디스크 꽉 참 등) — 토글은 화면에서 즉시 반영되고, 저장 실패는
  게임 내 채팅에 한 줄 경고만 남긴다. 토글 자체를 막지 않는다.
- **Fabric API 설치 실패** — 런처의 기존 에러 이벤트 경로를 그대로 탄다(`stage: "loader"`).
  모드팩 없이 바닐라+Fabric만으로 게임은 뜬다 — 클라이언트 설정 버튼만 없을 뿐.

## 테스트

**순수 로직 (JUnit, 게임 비의존)**:
- `FeatureRegistry` — 카테고리 필터, 검색, 즐겨찾기 정렬(즐겨찾기 우선, 그다음 카테고리
  순서, 그다음 이름순)
- `ModConfig` — 저장·로드 왕복, 손상된 파일 처리, 알 수 없는 id 무시, `configDir` 시스템
  프로퍼티 폴백

**런처 쪽 (기존 패턴)**:
- `JvmArgsBuilder`가 `-Dcubeclient.configDir=...`을 추가하는지
- 모드 jar 복사가 체크섬 일치 시 건너뛰는지

**게임 내 (사람이 직접, Task 8과 같은 방식)**:
- 타이틀/일시정지 화면에 버튼이 실제로 나타나는지, 바닐라 버튼과 겹치지 않는지
- 모드 목록 화면에서 FPS를 켜면 실제로 좌상단에 뜨는지, 끄면 사라지는지
- 게임 재시작 후에도 켠 상태가 유지되는지(설정 파일 왕복이 실기기에서도 되는지)
- 카테고리 탭, 검색, 즐겨찾기가 화면에서 실제로 동작하는지

화면 렌더링과 사용자 입력은 유닛 테스트로 못 잡는다 — Sub-project A에서 라이브 테스트로만
잡힌 버그가 여럿이었다는 걸 반복하지 않으려면, 이 부분은 처음부터 사람이 볼 계획으로 잡는다.
